# 始発駅の時刻の調査（2026-11-14）

対象は既存の `tests/fixtures/startTimeList.json.gz`・`startTimeList_holiday.json.gz` と
`tests/fixtures/wayback/*_startTimeList.json.gz` の30件。圧縮した元データを読むだけで調べた。
ダイヤの全 TrainInfo（未走行の臨時列車も含む）を数えており、ライブラリに登録される列車数とは異なる。

| 項目 | 延べ列車数 |
|:---|---:|
| 全列車 | 31,757 |
| `stationDepTime="-"` がある | 28,835 |
| `"-"` がなく、先頭駅に時刻がある | 2,922 |
| `"-"` の後に時刻の分かる駅がある | 28,835 |

通常の平日 fixture は1,157列車中94列車、土休日 fixture は982列車中92列車に `"-"` がなかった。
たとえば平日WDF番号2の先頭は寝屋川市05:37、その次は香里園05:40。
したがって設計プランの「始発駅の time はいつも None」は、データ全体には当てはまらない。
既存の実装は `"-"` がある駅を時刻不明の始発駅とし、ない場合は最初の停車駅を始発扱いにして、その時刻を保持している。
ただし、これが本当の始発駅か、公式データの経路が途中から始まっているのかは、このJSONだけでは確定できない。

公式ダイヤの列車フィールドは WDF番号・臨時フラグ・プレミアムカー・車両番号・駅ごとの情報で、
別のフィールドに始発の発車時刻はない。`stationDepTime` は発車時刻で、到着時刻・停車時間の列もない。

次に時刻が分かる駅から、他列車の同一区間の所要時間を引く案を調べた。
平日 fixture の連続する時刻既知の停車駅について、発車時刻差には次の幅があった。

| 区間 | 件数 | 発車時刻差 |
|:---|---:|:---|
| 香里園 → 寝屋川市 | 178 | 3〜10分 |
| 寝屋川市 → 香里園 | 177 | 2〜4分 |
| 北浜 → 淀屋橋 | 243 | 2〜3分 |
| 北浜 → 天満橋 | 239 | 1〜2分 |

発車時刻差には走行時間だけでなく、待避や次駅での停車時間も入るため、単純な逆算で定刻は一意に決まらない。
同じ停車パターン・時間帯・種別で絞れば推定幅を狭められる可能性はあるが、正確な始発時刻として埋める根拠には足りない。

別の案は駅別の公式時刻表との突き合わせだが、このAPIのWDF番号と別の時刻表を結ぶキーの確認が必要になる。
位置情報の履歴から発車した観測時刻を得る案も、1分ごとの座標の粗さ・取得開始前の欠測・実際の遅延があるため、定刻の復元には使えない。
今回は仕様どおり調査結果の報告にとどめ、時刻の補完や既存の値の変更は実装していない。
